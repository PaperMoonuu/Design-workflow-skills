# L1 × AI 设计评审

## 职责与边界

仅评审已经完成的单页局部 UI 改动，目标是在 15–30 分钟内给出可执行的设计风险与验收项。

- 聚焦结构、层级、任务路径、文案、局部一致性和可见状态。
- 不臆测接口、权限、埋点、审计或技术方案。
- 命中 L2 信号时，完成可见的 L1 局部评审并标记移交；不得以 L1 结论代替 L2 评估。
- 设计尚未完成时，说明不适用本 Skill，并转向设计前需求校准或交互方案预检。

## 输入与启动

要求用户提供以下最小输入：

1. 已完成的设计稿、改动前后稿或可评审原型。
2. 当前页面上下文。
3. 改动说明与业务目标。

可补充设计系统、开发约束、用户反馈、上下游页面、字段 / 配置 / 状态规则。

输入不全时，先索取缺失的最小信息。用户仍要求继续时，只能输出“基于假设的初评”：逐项列出假设和待确认项，不得给出“可进入开发”结论。

## 评审步骤

1. 确认设计阶段、页面数量和角色范围；判断是否符合单页局部 L1 改动。
2. 分离可见事实、合理假设和待确认项；只将事实用于结论。
3. 检查改动的影响面：页面结构与层级、任务路径、文案、局部组件和视觉一致性。
4. 逐项枚举相关状态：默认、选择、禁用、加载、空、错误、成功、长内容和窄屏 / 溢出。
5. 按模块类型补充检查：
   - 可写模块：可见的角色与生命周期提示、上传、提交、加载 / 失败、成功后的刷新或列表一致性。
   - 快捷提示词与输入插槽：默认 / 选中 / 关闭 / 溢出，空值 / 非法值 / 已填 / 取消 / 切换，以及提示词 ID、插槽值与最终 Query / 参数的一致性。
6. 判定优先级、提出可执行修改建议，并生成可供设计、开发、测试共用的验收清单。

## L2 升级规则

命中任一信号即标记“需 L2 移交”：权限或角色、生命周期或审计、上传与提交结果、接口字段或配置契约、多页面或多角色联动。

输出时写明：

- 已完成的 L1 局部走查范围；
- 触发升级的事实与尚缺的决策；
- 建议移交给产品、开发或测试确认的事项。

不要扩展处理 L2 问题，也不要把它们降级为纯视觉建议。

## 默认输出

默认给出精简评审报告；发现 P0、存在明显高风险，或用户明确要求时，再展开完整状态分析。


P0 表示阻塞进入开发或会导致关键任务失败；P1 表示应在本轮修订；P2 表示可排期优化。结论为“可进入开发（仅 L1）”时，仍须明确本次未覆盖的非 L1 范围。

## 功能、用法与场景

功能：将设计师的局部 UI 走查转成有优先级的风险、修改建议和可验收条目；同时防止权限、数据契约或跨页面规则被误判为 L1 问题。

调用示例：

- `使用 $l1-ai-design-review 评审这个 Figma 页面新增的附言模块。`
- `使用 $l1-ai-design-review 对比改动前后截图，检查这个筛选条件的交互与状态。`
- `请用 $l1-ai-design-review 审查首页快捷提示词点击后出现输入插槽的设计稿。`

适用场景：已完成设计稿后的字段、提示、筛选、局部模块、空 / 异常状态或单页交互改动；不适用场景：只有需求文档、未完成的方案、完整业务流程、跨页面 / 多角色专题，或需要直接产出开发规格。

## 持续验证

本 Skill 已基于两类真实案例发布：审批详情页附言模块，以及 OD 助手快捷提示词 / 输入插槽。后续以第 3 个不同类型的已完成 L1 改动继续校验边界稳定性；这不阻塞日常使用。
